
# CS 320 - Software Testing, Automation, and Quality Assurance

## Module Eight Portfolio Reflection

### 1. How can I ensure that my code, program, or software is functional and secure?

I think one of the most important ways to make sure software is functional and secure is through consistent testing. Throughout this course, I learned how to use JUnit to create automated tests that check whether different parts of a program work as expected. For example, when working on the ContactService project, I tested things like adding, deleting, and updating contacts while making sure the program followed the requirements. Testing invalid inputs was also important because it helped identify potential problems before they could affect the application. I also learned that testing should be an ongoing part of development rather than something done only at the end. While unit testing helps verify functionality, secure software also requires input validation, careful handling of data, and additional security testing.

### 2. How do I interpret user needs and incorporate them into a program?

I approach user needs by first understanding what the application is supposed to accomplish and identifying the requirements that need to be met. In the ContactService project, the requirements explained how contacts should be created, stored, updated, and deleted. I used those requirements to determine what methods the program needed and what tests I should write. For example, contact IDs needed to be unique, and certain fields had specific length restrictions. By turning those requirements into test cases, I could check whether the program behaved the way it was supposed to. I think understanding user needs is important because even if a program runs without errors, it isn't successful if it doesn't do what the user actually needs.

### 3. How do I approach designing software?

When designing software, I like to start by breaking the requirements into smaller parts so I can better understand how everything should work together. This course helped me see the importance of keeping code organized and making sure each class has a clear responsibility. For example, separating the Contact class from the ContactService class made it easier to manage contact information and test the different operations. I also learned how useful automated testing can be during development because it allows me to catch problems as changes are made. Moving forward, I plan to continue using this approach by reviewing requirements, organizing my classes and methods, writing tests, and improving the code when necessary. Overall, this course helped me understand that good software design involves more than just getting a program to run. It also needs to be reliable, maintainable, and designed around the user's needs.
